# 面试复盘

把一场已完成的面试转换成完整、严格、可执行的 Markdown 复盘。保留事实与原话证据，避免泛泛鼓励和无依据推测。

## 隐私边界

- 只读取用户明确提供或授权访问的材料，并只将报告保存到用户确认的位置。
- 当目标位置为公开仓库或公开链接时，先替换个人姓名、联系方式、公司内部信息、账号标识、内部绝对路径、凭据和访问令牌；绝不复述密钥原文。
- 不把真实逐字稿、简历、生成报告或运行日志复制到 Skill 目录或公开仓库。公开示例使用合成数据并明确标注。

## 工作流

### 1. 读取材料

- 接受用户粘贴的逐字稿，或本地可读取的 TXT、Markdown、DOCX、PDF 文件。
- 遇到 DOCX 或 PDF 时，使用当前环境中适合该格式的读取能力提取正文。
- 将音频或视频转写视为独立流程；获得逐字稿后再开始复盘。

### 2. 一次性补齐前置信息

开始分析前，检查并在一条消息中询问所有缺失项：

- 面试日期
- 公司
- 岗位
- 轮次（一面、二面、HR 面或用户提供的其他轮次）

用户明确不知道某项时，将其记为“未知”，不要继续追问。只有用户要求岗位匹配或 JD 对标分析时，才询问缺失的 JD。

同时检查逐字稿是否包含候选人向面试官提问的反问环节。若未识别到，先询问用户是没有反问、未被记录，还是需要补充内容。若逐字稿明确在某处中断或听不清，保留所有可确认信息，并标记“逐字稿在此处中断／无法确认”；不得根据上下文补写事实。

### 3. 确认本次输出位置

- 用户已经提供保存位置时，直接使用，不重复确认。
- 用户未提供时，必须在分析前询问。先解析当前工作目录，再给出建议的绝对路径，不要只显示相对路径：
  `<当前项目>/outputs/interview-retrospect/YYYY-MM-DD-公司-岗位-轮次-面试复盘.md`
- 允许用户确认建议路径、提供其他路径，或选择“本次不保存，只在对话中输出”。
- 目标文件已存在时，询问用户选择覆盖、改名或取消保存；不得自行覆盖。

把缺失的面试信息、反问环节状态和保存位置合并到同一轮提问中，减少往返。

### 4. 按证据评估

分析前完整读取：

- `references/evaluation-framework.md`：轮次标准、评分和 P0/P1/P2 规则
- `assets/report-template.md`：报告结构与反问环节格式

执行以下要求：

1. 按逐字稿顺序记录每个面试官问题。
2. 常规问题只总结候选人的回答，不大段重复逐字稿。
3. 每题给出问题类型、回答摘要、原话证据、反思和理想回答框架。
4. 每题反思以且仅以一个标记开头：
   - `✅`：回答有效，无需专项追练
   - `🟡`：可以优化推理、证据或表达
   - `🔴`：存在影响岗位判断的关键缺口
5. 按四个维度评分：项目深度、产品思维、逻辑表达、行业潜力。每项说明必须引用逐字稿证据。
6. 按轮次和证据划分 P0、P1、P2。追问本身只是一条重要信号；追问明确暴露核心能力缺口、事实错误、逻辑断裂或关键证据不足时，才判为 P0。
7. 提炼表现亮点、下一轮准备计划和可迁移训练。面试发现本身不等同于已经完成训练。
8. 仅在逐字稿支持时生成面试官画像、岗位信号和下一轮方向预测，并标明这是基于证据的判断。

### 5. 完整整理反问环节

逐组整理候选人向面试官提出的问题。每组必须包含：

1. 候选人的原始问题
2. 面试官的完整回答
3. 关键原话
4. 回答透露的业务、团队或岗位信息
5. 对候选人求职判断的影响
6. 后续值得验证的问题

“完整回答”应结构化重组表达顺序，同时保留所有可确认的事实、例子、条件、因果、判断和态度。关键原话单独引用。不得把面试官的多段回答压缩成一句笼统摘要。

如果用户确认没有反问或没有相关记录，保留“面试反问环节”章节并如实注明情况。

### 6. 生成并验证报告

- 严格使用 `assets/report-template.md` 的九段式结构。
- 只生成一份完整 Markdown 报告，不创建精简归档、长期记忆或跨场次索引。
- 保存报告后，先把脚本路径解析为相对于本文件所在 skill 目录的绝对路径，再运行：
  `python3 <skill目录>/scripts/validate_retro_report.py <报告路径>`
- 验证失败时修正报告并重新运行，直到通过。
- 用户选择不保存时，按同一模板在对话中提供完整报告，并自行检查所有必需章节。

### 7. 返回结果

- 已保存：在对话中给出简洁结论、最高优先级改进项和报告的可点击绝对路径链接。
- 未保存：先给简洁结论，再给完整 Markdown 报告。
- 默认使用中文；用户明确指定其他语言时切换。

## 质量底线

- 使用逐字稿中的证据，不从沉默或缺失信息推断表现。
- 不因缺少 JD 拒绝普通面试复盘。
- 区分轮次特有标准与通用的沟通、推理问题。
- 保持批评具体、可验证、可执行。
- 不写固定的本机目录，不写入用户未指定的外部平台，不维护外部记忆。
